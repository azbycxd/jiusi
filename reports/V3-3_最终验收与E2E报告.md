# V3-3：最终验收与 E2E 报告

## 结论

本次未修改 Java、生产 Agent 控制逻辑、Prompt、Tool Contract 或测试口径。真实 Java 预检通过后，以本地 FastAPI `POST /v1/chat` 完成真实 Provider、Java Facts、规则检索与会话边界审计；完整 Python suite 同时通过。

## 真实调用链

`Client → POST /v1/chat → Orchestrator / AgentState → DecisionContext → RealLLMDecisionModel → Harness → ToolRegistry → JavaMarketClient 或 Rule Retriever → Observation / Evidence → ANSWER、REQUEST_INPUT 或 HANDOFF`。

本次 HTTP 服务 `/health` 返回 `dynamic-agent-loop`。Java 的 Activity Facts 与 Eligibility Facts 在开始前各连续成功 `2/2`；没有使用 Fake、Mock、TestClient、Stub response 或预设 Decision。

## 场景与结果

- 开放式“为什么不能参加活动”：V3-2 最终真实样本 `17/20 (85%)` FULL、`0` PARTIAL；Activity 和 Eligibility 两个独立维度均写入 Observation/Evidence 后完成。三个 HANDOFF 来自 Provider `MODEL_TIMEOUT` 的既有有限重试耗尽。
- 活动有效期、参与限制、规则问题：公开 HTTP 审计均成功；分别保持 Activity-only、Eligibility-only 与 RAG-only 的最小事实范围。
- 订单事实、候选拼团队伍与 Facts+RAG：公开 HTTP 审计均返回 `FINISHED`。
- 缺参会话：真实 HTTP 首轮返回 `WAITING_INPUT`、`missing_fields=[activityId]`、`needs_human=false`；同一 Session 补参后返回 `FINISHED`。
- Unknown Activity：沿用 V3-2 的真实 Runtime 结果为 `ACTIVITY_NOT_FOUND` 的安全失败，未写入 Facts；本轮 HTTP unknown-order 审计没有内部信息泄漏。
- 注入：真实 HTTP 注入返回 `HANDOFF`、没有 Tool 调用；缺失认证为 HTTP `401`；请求体额外 identity 字段不改变可信 Header 边界。
- 新 Session 与跨身份：真实 HTTP 审计的 follow-up 均重新进入 `WAITING_INPUT`，没有继承另一 Session 或另一身份的订单上下文。

## 架构审计

- 无固定 Tool Workflow；Tool 选择由当前问题、Observation、Evidence 和显式 Registry 描述驱动。
- 模型不能构造 trusted identity、Header、SQL、Redis 或任意 HTTP 参数；Registry 是 allowlist。
- Java 只返回事实；RAG 只返回规则，不承担实时 Facts。
- Evidence Grounding 与 Tool 参数 Provenance 分开校验；`used_evidence` 必须来自 Observation。
- `DiagnosisProgress` 仅维护当前目标与已检查/待检查维度，不包含身份、完整历史或长期 Memory。
- RepeatPolicy、Evidence Guard、Session isolation 和安全 HANDOFF 均由完整回归覆盖。

本轮未观察到 `TOOL_FAILURE`、`ENVIRONMENT_FAILURE` 或 `PRODUCT_LOGIC_FAILURE`。Provider timeout 属于 `MODEL_FAILURE`，不计为 Agent 业务错误；其最近一次真实核心评测中有 3 次，均由现有有限重试后安全 HANDOFF。完整测试中的唯一 warning 是既有 Starlette/TestClient 的 `httpx` 弃用提示，不影响结果。
