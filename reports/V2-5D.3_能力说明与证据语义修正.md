# V2-5D.3：能力说明与证据语义修正

## 1. V2-5D.2 的唯一失败点

V2-5D.2 的真实能力咨询中，模型没有调用工具，且能力说明本身正确；但把
`available_tools.get_order_facts.description` 和
`available_tools.get_joinable_team_facts.description` 写进了 `used_evidence`。这两个路径不是已执行 Tool 的业务事实，因此被 Hard Evidence Guard 正确拒绝为 `MODEL_EVIDENCE_NOT_AVAILABLE`。

## 2. Runtime 能力元数据与 Observation Evidence

`available_tools` 是当前运行时可执行能力的元数据，可用于说明 Agent 能力边界；它不是外部业务事实。

`observations` 和其中的 `evidence` 只来自已经执行的 Tool，代表可验证的业务事实。两者保持隔离：没有把 `available_tools.*` 加入 Evidence Contract，也没有增加任何新的 Evidence 类型。

## 3. used_evidence 最终语义

`used_evidence` 只声明最终 ANSWER 实际使用的 Observation-derived Evidence 路径。

- 纯能力说明可依据 `available_tools` 生成，必须使用 `used_evidence=[]`。
- 任何表述已查询到的业务事实的 ANSWER，必须引用 `DecisionContext.evidence` 内真实存在的对应路径。

## 4. Prompt 最小修改与 Hard Guard

仅修改 `decision/real_llm.py` 的 `SYSTEM_PROMPT`，明确：

- `used_evidence` 仅可复制 `DecisionContext.evidence` 条目的 `kind` 字符串，不能引用如 `evidence[0]` 的数组位置；
- 不得引用 `available_tools`、Tool 描述、`parameters_schema`、system prompt、用户问题或认证/运行时元数据；
- 仅说明能力时使用 `used_evidence=[]`；业务事实回答必须引用对应 Observation Evidence。

没有修改 `decision/validation.py`。Hard Evidence Guard 持续拒绝 `available_tools.*`、虚构路径及不存在的 Observation path。

## 8. 核心 Multi-Tool Prompt Regression Smoke

首次真实运行中，两个 Tool 均成功执行，但最终模型误把 `evidence[0]` 等数组位置作为 `used_evidence`。Hard Evidence Guard 正确拒绝该结果为 `MODEL_EVIDENCE_NOT_AVAILABLE`，没有放宽验证器。随后在本阶段 Prompt 中补充“复制 `kind` 字符串、不能引用数组位置”的最小澄清，并重新执行完整测试与真实烟测。

最终真实烟测成功完成：

```text
MODEL_DECISION(CALL_TOOL get_order_facts)
-> TOOL_RESULT(success, 16 ms)
-> MODEL_DECISION(CALL_TOOL get_joinable_team_facts)
-> TOOL_RESULT(success, 12 ms)
-> MODEL_DECISION(ANSWER)
-> FINISHED
```

第一次模型调用发生一次 `MODEL_TIMEOUT`（60,570 ms）并按既有有限模型重试恢复。最终 `tool_call_count=2`、`retry_count=0`、`model_call_count=4`、`model_retry_count=1`。真实 Observation 包含订单/团队/活动事实，以及空 `candidate_teams` 的 Evidence；最终模型引用的全部六个路径均为实际 `kind` 值：

```text
get_order_facts.order.status
get_order_facts.team.status
get_order_facts.team.target_count
get_order_facts.team.complete_count
get_order_facts.activity.status
get_joinable_team_facts.candidate_teams
```
