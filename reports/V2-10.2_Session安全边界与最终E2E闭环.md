## 2. 当前 Session Contract

`/v1/chat` 从请求体接收 `session_id` 和 `message`，可信身份仅来自 HTTP Header，不能由请求体传入。`SessionMemory` 是进程内 `dict[session_id, AgentState]`，以 deep copy 保存完整 `AgentState`，因此其中可包含 Context、Observation、Evidence、Tool history 和 Control state。

恢复时 Orchestrator 会在以下任一条件下新建 State：Session 不存在、保存的 `authenticated_user_id` 与当前可信身份不同、或保存的 State 已是 `FINISHED` / `FAILED` / `HANDOFF`。因此当前设计只恢复**未终态**的同身份任务；终态后的 follow-up 是新任务，不支持省略订单/activity 参数的跨轮延续。

## 3. Session A：同一 Session

第一轮订单查询经真实 HTTP 返回 `200 / FINISHED`。Trace 是：

```text
MODEL_DECISION(CALL_TOOL)
```

第二轮在相同 Session 中省略实体参数，返回 `200 / HANDOFF`。该轮 Trace 从全新的 iteration/model count 开始，只有一次 `MODEL_DECISION(HANDOFF)`，没有 Tool 调用或旧 Observation；行为符合上述终态重置契约。

## 4. Session B 隔离

新的 Session B 直接发送同一省略实体的追问，返回 `200 / HANDOFF`，Trace 同样只有 `MODEL_DECISION(HANDOFF)`，无 Tool 调用。它没有获得 Session A 的 outTradeNo、activityId、Observation、Evidence、Tool history 或业务上下文。

## 5. 同 Session、不同可信身份

Identity A 先在 Session X 完成真实订单查询；Identity B 再使用相同的 Session X 发送省略实体追问。B 返回 `200 / HANDOFF`，其 Trace 以新的 State 计数开始，且没有 Tool 调用或可复用业务上下文。

根因是 Orchestrator 恢复条件显式比较 `state.authenticated_user_id != authenticated_user_id` 并创建新 State。报告中只使用 Identity A / Identity B 标签；没有记录真实身份值或 Header。

## 6. Unknown Order 安全边界

以明确的、测试专用且不存在的订单标识经真实 `/v1/chat` 发起请求。Trace：

```text

→ get_order_facts
```

Tool 实际调用 1 次、retry 为 0。公开 HTTP 响应为 `200 / FINISHED`，只给出统一的“订单不存在或当前账号无权查看”的安全语义；未包含 Tool error code、SQL、表名、Mapper、Java exception 或 stack。这保持“不存在”和“无权查看”不可区分。

## 7. Facts + RAG ×3

三个独立 Session 都返回 `200 / FINISHED`（`3/3`）。每个真实 Trace 都是：

```text
MODEL_DECISION(CALL_TOOL)
→ get_order_facts (success)
→ MODEL_DECISION(CALL_TOOL)
→ search_group_buy_rules (success)
→ MODEL_DECISION(ANSWER)
```

每次 2 次 Tool 调用、0 次 Tool retry。`DecisionStage` 在持久化 ANSWER 前完成 Evidence Validation；三条 Trace 没有 `MODEL_VALIDATION_ERROR`，也没有 evidence-not-available / contract-mismatch 终态。`used_evidence` 不属于公开 HTTP response 或 Trace 的输出契约，故未记录 Provider 原文；其验证门由运行时完成。

## 9. Failure Propagation、Trace 与 Redaction

V2-10.1 的 HTTP deterministic regression 已随完整 pytest 回归：Java connection failure 的有限 retry / HANDOFF，以及 Provider timeout 的恢复和有限终止仍被覆盖。此阶段没有为了“更真实”停止 Java 或改变 Provider。

真实 Trace 记录 stage、action、tool name、success、error code、duration、iteration、Tool/model counts 与 token telemetry；未写入认证 Header、可信身份、API key、完整 Prompt、完整 Provider response 或 Java stack。安全结构化结果见 [V2-10.2_live_http.json](/D:/workspace/java/group-buy-agent/reports/evals/V2-10.2_live_http.json) 和 [V2-10_http_smoke.json](/D:/workspace/java/group-buy-agent/reports/evals/V2-10_http_smoke.json)。
