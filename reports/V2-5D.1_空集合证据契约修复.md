# V2-5D.1：空集合 Evidence Contract 修复

## 1. V2-5D 真实失败点

V2-5D Run #1 已通过真实 Provider 与 Java 完成：

```text
get_order_facts
→ Observation #1 (references.activity_id=100123)
→ get_joinable_team_facts(activityId=100123)
→ Observation #2 (candidate_teams=[])
→ ANSWER
```

真实模型在最终 ANSWER 中引用 `get_joinable_team_facts.candidate_teams` 来表达“本次查询没有返回候选团队”。此前该路径没有 Evidence，因此 Harness 正确返回 `MODEL_EVIDENCE_NOT_AVAILABLE` 并进入 HANDOFF。

## 2. 根因

审计确认：

- `agent/state.py::_data_paths()` 对非空 list 递归产生 `candidate_teams.0.<field>` 等叶子路径；
- 对空 list 直接返回空字典，不产生 `candidate_teams` 本身；
- `JoinableTeamFactsTool` 只在遍历候选团队时生成候选团队 Evidence，空数组时不会进入该循环。

因此 `candidate_teams=[]` 虽然存在于 Observation data，却无法成为可验证、可引用的 Evidence node。

## 3. 为什么空集合是可验证事实

空集合不是缺失或 Tool Error。`candidate_teams=[]` 精确表示这一次可信查询没有返回候选团队，可以支撑有限、可验证的表述：

> 本次查询没有返回候选团队。

它不代表活动绝对不存在其它团队，也不改变 statistics 的 SQL 统计语义。

当前 `Evidence.value` Contract 为字符串，所有 scalar data node 均以 `str(value)` 比对。因此空集合 Evidence 使用从真实 normalized data 派生的 canonical 值 `"[]"`；Observation data 本身仍是实际 list `[]`，没有使用“no candidates”或 `0` 等诊断/替代值。

## 4. 修改前后的 data path 语义

| 数据节点 | 修改前 | 修改后 |
| --- | --- | --- |
| `candidate_teams=[]` | 没有可验证路径 | terminal path `candidate_teams`，值 `"[]"` |
| 非空 `candidate_teams` | 索引叶子，如 `candidate_teams.0.team_id` | 保持不变 |
| `candidate_teams.0.*`（空列表） | 非法 | 仍非法 |
| 任意 parent collection（非空列表） | 未自动开放 | 仍未自动开放 |

实现仅在通用 `_data_paths()` 遇到空 list 时将当前路径作为 terminal node；没有引入 JSONPath、Tool-name 特判、越界访问或父集合普遍放开。

## 5. Joinable Team 空候选 Evidence

当 `facts.candidate_teams` 为空，`JoinableTeamFactsTool` 追加：

```text
ToolResult evidence: candidate_teams = "[]"
Observation evidence: get_joinable_team_facts.candidate_teams = "[]"
```

非空候选列表仍只输出各个索引下的字段 Evidence，例如 `candidate_teams.0.team_id`。Tool 仍只输出 Facts，不生成诊断文本。

## 6. Evidence 严格性与多 Observation

新增测试确认以下路径继续触发 `MODEL_EVIDENCE_NOT_AVAILABLE`：

- `get_joinable_team_facts.candidate_teams.0`
- `get_joinable_team_facts.candidate_teams.0.team_id`（空列表）
- `get_joinable_team_facts.candidate_teams.99.team_id`
- `get_joinable_team_facts.fake_field`
- `get_joinable_team_facts.statistics.fake_count`
- 不存在 Tool 的 evidence path

同时，受控两 Tool 链测试验证 `get_order_facts` Observation 与空候选 `get_joinable_team_facts` Observation 会同时进入第三轮 DecisionContext，最终 ANSWER 可同时引用订单 Evidence 和 `get_joinable_team_facts.candidate_teams`，且正常 `FINISHED`。没有恢复 ContextState.evidence 副本、facts 字段或任何 Tool 专属 State。
