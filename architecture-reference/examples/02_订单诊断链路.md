# 订单诊断链路

## 用户输入

`我的订单 644398015396 现在是什么状态？`

## Task / Intent / RoutingResult

任务是订单事实诊断，Intent=`ORDER_DIAGNOSIS`。

```json
{"skill_name":"order_diagnosis","entities":{"outTradeNo":"644398015396"},"confidence":0.98,"source":"RULE"}
```

## SkillSpec 摘要

required entity=`outTradeNo`；possible dimensions 包括 order_state 与可选 rule_explanation；本次 required 只有 order_state；RAG 非必需。

## 初始 AgentState

```json
{"task_status":"SKILL_ACTIVE","routing_entities":{"outTradeNo":"644398015396"},"observations":[],"skill_progress":{"required_dimensions":["order_state"],"obligation_status":{"order_state":"PENDING"}}}
```

## DecisionContext #1

包含问题、订单 Skill 中文指令、Progress、`get_order_facts` 自描述。认证身份被排除。

## LLM Decision #1

```json
{"action":"CALL_TOOL","tool_name":"get_order_facts","tool_arguments":{"outTradeNo":"644398015396"}}
```

## Harness Validation

- Capability：Tool 属于 Skill allowlist。
- Argument：字符串格式合法。
- Identity：arguments 无 userId/header/token。
- Provenance：outTradeNo 与用户实体精确一致。
- Repeat/Loop/Budget：首次调用且预算内。

## Tool Call / ToolResult

Java client 从可信 State 注入身份，Stub 不发真实 HTTP。

```json
{"success":true,"source":"java_market","data":{"order":{"status":"CLOSE"},"team":{"status":"PROGRESS","target_count":3,"complete_count":0}}}
```

## Observation / Evidence / Progress

Observation 保留成功事实快照；Evidence 可寻址。order_state Obligation 要求的 `get_order_facts.order.status` 存在，因此 SATISFIED；其它 team 字段可供答案引用，但不是强制把所有返回字段都设为完成义务。

## State 更新

tool_call_count=1；ToolResult 和 Observation 均保留；没有 `diagnosis_code` 或 Java 给出的最终原因。

## DecisionContext #2 / 最终 Decision

```json
{"action":"ANSWER","final_answer":"订单状态为 CLOSE；关联拼团队伍仍为 PROGRESS，目标 3 人，当前完成 0 人。","used_evidence":["get_order_facts.order.status","get_order_facts.team.status","get_order_facts.team.target_count","get_order_facts.team.complete_count"]}
```

Completion 与 Evidence 校验通过后 State=`COMPLETED`。

## Trace 摘要

`ROUTED → MODEL_DECISION(CALL_TOOL) → TOOL_CALL(get_order_facts) → TOOL_RESULT(success) → OBSERVATION → MODEL_DECISION(ANSWER) → COMPLETED`

## 为什么不是固定 Workflow

该问题只有一个直接相关维度，所以一次 Tool 足够；这是 Skill completion scope 的结果，不是系统对所有问题固定调用 Order Tool。
