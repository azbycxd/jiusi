# 参团失败诊断：两条合法动态链路

## 用户输入

`为什么我参加不了活动 100123？`

可信身份来自 RequestContext，不出现在下面任何 Tool arguments。

## Task / Intent

- task：解释当前用户在指定活动中无法参与的可验证原因。
- intent：`PARTICIPATION_DIAGNOSIS`。
- required entity：`activityId=100123`。

## RoutingResult

```json
{"intent":"PARTICIPATION_DIAGNOSIS","skill_name":"participation_diagnosis","entities":{"activityId":100123},"source":"RULE","intent_switch":false}
```

Router 到此结束；它没有决定先查 Activity 还是 Eligibility。

## SkillSpec 摘要

- allowed_tools：`get_activity_facts`、`get_user_eligibility_facts`、必要时 `search_group_buy_rules`。
- possible_dimensions：`activity_validity`、`user_eligibility`、`rule_explanation`。
- required_dimensions：当前开放诊断只取前两个，不强制规则解释。
- completion：两个 Required 的全部 Evidence Conditions 均 SATISFIED，且答案引用有效 Evidence。
- failure：可补实体用 REQUEST_INPUT；无法取得关键事实用 HANDOFF。

## 初始 AgentState

```json
{"task_status":"SKILL_ACTIVE","routing_entities":{"activityId":100123},"observations":[],"tool_results":[],"skill_progress":{"goal":"解释无法参与原因","required_dimensions":["activity_validity","user_eligibility"],"obligation_status":{"activity_validity":"PENDING","user_eligibility":"PENDING"}}}
```

## 合法路径 A：Activity → Eligibility → ANSWER

### DecisionContext #1

只含当前问题、Progress、三个 Skill Tool 描述；不含 auth、Header、完整历史。

### LLM Decision #1

```json
{"action":"CALL_TOOL","tool_name":"get_activity_facts","tool_arguments":{"activityId":100123}}
```

### Harness Validation #1

Decision Contract → Capability → Argument Schema → Identity → Parameter Grounding(activityId 来自用户) → Repeat → Loop/Budget，全部通过。

### Tool Call / ToolResult #1

```json
{"tool":"get_activity_facts","arguments":{"activityId":100123}}
{"success":true,"source":"java_market","data":{"activity":{"status":"EFFECTIVE","within_valid_time":true,"activity_id":100123}}}
```

### Observation / Evidence / Progress #1

```json
{"observation_id":"obs-a","tool_name":"get_activity_facts","data":{"activity":{"status":"EFFECTIVE","within_valid_time":true,"activity_id":100123}}}
```

Evidence：status 与 within_valid_time 都存在，因此 activity_validity=SATISFIED；user_eligibility=PENDING。若 Tool success 却缺 within_valid_time，Activity Observation 仍存在，但 activity_validity 继续 PENDING。此时 ANSWER 会被 CompletionGuard 拒绝。

### DecisionContext #2 与 LLM Decision #2

Context 新增 Activity Observation 和 remaining eligibility。模型决定：

```json
{"action":"CALL_TOOL","tool_name":"get_user_eligibility_facts","tool_arguments":{"activityId":100123}}
```

### Harness / ToolResult #2

activityId 仍有用户来源，身份由运行时注入。

```json
{"success":true,"source":"java_market","data":{"eligibility":{"participation_limit_reached":false,"tag_participation_allowed":false,"market_downgraded":false,"user_within_release_range":true}}}
```

### Observation / Evidence / Progress #2

四个 Eligibility Conditions 均有 Evidence；false 也按“路径存在”满足。user_eligibility=SATISFIED，remaining=`[]`。

### DecisionContext #3 与最终 Decision

```json
{"action":"ANSWER","final_answer":"活动当前有效且仍在有效期内，但参与标签条件未通过。","used_evidence":["get_activity_facts.activity.status","get_activity_facts.activity.within_valid_time","get_user_eligibility_facts.eligibility.tag_participation_allowed"]}
```

CompletionGuard 先确认 remaining 为空，EvidenceGuard 再逐路径解析，状态转 `COMPLETED`。

## 合法路径 B：Eligibility → Activity → ANSWER

Decision #1 可先取得完整 Eligibility Evidence；user_eligibility=SATISFIED、activity_validity=PENDING。模型不能因为找到一个原因就提前回答。

Decision #2 再调用 `get_activity_facts(activityId=100123)`，得到 status=EFFECTIVE；Progress 清空。最终 ANSWER 使用与路径 A 相同的三条 Evidence。

两条路径的顺序不同，但完成条件相同：Query-scoped Required Obligations 完整 + used_evidence 可解析。Condition 允许多个 accepted_paths，因此约束的是 Evidence，不是固定 Tool 名。

## Trace 摘要

`ROUTED → SKILL_ACTIVE → MODEL_DECISION → TOOL_CALL → TOOL_RESULT → OBSERVING → MODEL_DECISION → TOOL_CALL → TOOL_RESULT → OBSERVING → MODEL_DECISION → ANSWER_VALIDATED → COMPLETED`

## 为什么不是固定 Workflow

Skill 只给 required dimensions 和 allowed tools；模型可以选择 A 或 B。Progress 只阻止遗漏/过查，不表达箭头顺序；RAG 也不是强制步骤。
