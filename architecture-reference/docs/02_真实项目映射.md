# 真实项目映射：唯一事实表

这张表是 Reference 与真实项目关系的中央口径。A=真实已实现，B=职责重构抽象，C=生产化扩展设计。A/B 表示语义已存在但 Reference 将职责显式化。

| Reference Component | 层 | 真实项目对应 / 工作方式 | 为什么重构 | 面试推荐说法 | 禁止说法 |
|---|---|---|---|---|---|
| RequestGateway | A/B | HTTP `/v1/chat` 解析请求并建立认证上下文 | 将协议适配与 Agent Loop 分开 | 入口只接收可信身份，不让模型构造身份 | 模型决定 userId |
| IntentRouter | A/B | 基于当前任务和输入识别 intent | Router 只选任务，避免退化为固定 Workflow | Router 选择 Skill，模型在 Skill 内动态选动作 | Router 编排 Activity→Eligibility |
| SkillSpec / Requirement | B | Prompt、Tool metadata、最小 DiagnosisProgress 的进一步 Reference 重构 | 分离 Possible 能力空间与 Query-scoped Required | v1.1 约束 Evidence 义务，不固定 Tool | 线上已部署 Evidence Obligation 框架 |
| SkillRegistry | B | 真实项目能力集合的参考注册层 | Router 不直接构造能力对象 | Registry 是显式能力 allowlist | 自动扫描任意函数注册 |
| Skill Prompt | A/B | 真实 System Prompt 中的任务约束被按 Skill 拆分 | 降低无关指令与冲突 | 中文 Prompt 描述目标，不替代硬 Guard | Prompt 能保证安全 |
| AgentState | A | 保存 session、task、Observation、Evidence、计数与状态 | 明确谁拥有可恢复状态 | State 是任务工作状态，不是完整聊天记录 | State 就是 Context/Trace |
| DecisionContext | A/B | 真实 Context Builder 的最小模型投影 | 防止身份和历史噪声进入模型 | Context 按本轮决策选择最小充分信息 | 把整个 State 序列化给模型 |
| Orchestrator | A | 推进 Router、Model、Harness、Tool 与终态 | 收敛状态转换但不承载全部规则 | Orchestrator 推进流程，Harness 执行约束 | Orchestrator 是业务规则引擎 |
| HarnessRuntime | A/B | 真实 Harness/Evidence/Repeat/预算规则的统一参考入口 | 避免 Orchestrator 复制 Guard | 它只组合确定性约束，不做业务推理 | Harness 决定诊断原因 |
| ToolRegistry | A | 当前仅允许 5 个 Tool | 防止任意函数执行 | 双层 allowlist：全局 Registry + Skill allowed_tools | Agent 能调 shell/SQL |
| Java Facts Tools | A | Order/Activity/Eligibility/Joinable Team 通过 Java HTTP 取事实 | Java 事实与模型诊断解耦 | Java 只给可信 Facts，LLM 基于 Evidence 解释 | Java 返回最终 LLM 诊断 |
| Rule Search Tool | A | 本地词法 Catalog 检索规则 | 规则知识与实时状态分源 | RAG 解释规则，不查询订单实时状态 | RAG 能替代 Java Facts |
| ToolResult | A | success/error/retryable/source/data 明确映射 | 区分执行失败与业务事实 | HTTP 200 也要验证 envelope/code/schema | 函数没异常就是成功 |
| Observation | A/B | 成功 ToolResult 规范化为模型可见事实 | 失败不能污染业务上下文 | Observation 是带来源和时点的事实快照 | 超时说明用户不符合条件 |
| Evidence | A | 精确路径验证 `tool.field` 引用 | 阻止模型用不存在的事实回答 | 答案引用必须可在 Observation 解析 | Evidence 是模型理由文本 |
| ParameterProvenance | A/B | 参数必须源自用户实体或既有 Observation | 阻止模型凭空构造 activityId/userId | Provenance 管参数来源，Evidence 管答案依据 | Schema 合法就代表来源可信 |
| SkillProgress | A/B | A 层仍是最小 DiagnosisProgress；B 层 v1.1 用 Obligation 状态细化 | 同时阻止提前回答和 Tool-success 粗粒度完成 | 记录 Required、PENDING/SATISFIED 与缺失 Condition | 固定 Activity→Eligibility 工作流 |
| CompletionPolicy | A/B | 真实 Progress + Harness；Reference v1.1 Query-scoped 完成 | 将“信息充分”从 Tool 调用升级为 Evidence 义务 | Required Obligations 满足且答案 Evidence 有效才完成 | Tool success 就算 Dimension complete |
| FailurePolicy | A/B | ToolResult 错误映射、有限重试与 HANDOFF | 按能力/可恢复性区分失败 | REQUEST_INPUT 是可补参，HANDOFF 是能力或可靠性不足 | 所有失败都让用户重试 |
| SessionMemory | A | 进程内按 session+identity 保存 State | 支持 WAITING_INPUT 同会话恢复 | 当前是单进程短期任务记忆 | 已实现跨实例持久化 |
| TaskStore | B/C | Reference 展示同 Session 切题时暂停旧 Task | 明确多任务隔离责任 | 是多任务会话的接口设计，非真实生产存储 | 已上线任务编排平台 |
| LongTermMemory | C | 未实现 | 未来个性化需独立治理 | 不用长期记忆替代实时 Facts | 系统会永久记住用户 |
| Eval | A/B | 真实阶段有 pytest、live eval、HTTP E2E；Reference 抽象分类器 | 分开模型、Tool、Context、Evidence、Infra 失败 | 指标必须绑定阶段和样本 | 23/23 等于生产准确率 100% |
| Trace / Metrics | A/B | 真实 Trace 记录阶段、调用、耗时；Reference 提供 Recorder | 支持安全诊断与回归 | 记录结构化事件且脱敏 | 保存完整 Prompt/API Key |
| Performance | C | 仅有局部耗时/Token 观测，无正式容量数据 | 为后续压测预留口径 | 尚无 P95/QPS/SLA 结论 | 已达到生产高并发 |
| Hybrid RAG / VectorDB / Rerank | C | 未实现；当前为小规则集词法检索 | 规模和语义歧义出现后再升级 | 先用 Eval 证明召回瓶颈 | 已使用向量数据库 |
| MCP | C | 未实现 | 跨系统工具标准化时再评估 | Tool Contract 可映射 MCP，但当前没有接入 | 这是 MCP Agent |
| Multi-Agent | C | 未实现，当前单 Agent + 多 Skill | 只有角色隔离和并行收益超过成本才引入 | Skill 不等于 Agent | 每个 Skill 都是 Agent |
| A2A | C | 未实现 | 多 Agent 跨进程协作后才需要 | 是未来互操作协议候选 | 当前已支持 A2A |
| Write Tool | C | 未实现，当前全是只读查询 | 写操作需幂等、审批、补偿、审计 | 写 Tool 安全成本远高于读 Tool | Agent 可修改订单 |

## 使用规则

1. README、案例和面试材料若与此表冲突，以本表的 A/B/C 定义为准。
2. C 层文件必须标注“【生产化扩展设计，当前真实项目未实现】”。
3. 真实指标只能描述当时样本和阶段；不得外推为生产准确率、吞吐或 SLA。
4. Reference 的可运行测试证明对象协作逻辑可读，不证明它是当前生产部署代码。
