# 大厂面试连续追问树

本页按 14 个“主问题”组织。每个主问题使用固定结构；编号问题是可继续下钻的追问池。回答时始终区分 A 真实实现、B 参考重构、C 未实现生产扩展。

## A. 项目（15+）

**问题：你解决的核心问题是什么？**

- 30 秒口述：把拼团客服从自由生成升级为 Evidence-Grounded Diagnosis Agent；模型动态选 Tool，但身份、参数、证据和终止由确定性代码约束。
- 深挖：一次请求经过 Gateway→Skill→Context→LLM→Harness→Tool→Observation→Evidence→Completion。
- 当前项目：5 个只读 Tool、Java Facts、词法 RAG、多轮补参和真实 E2E。
- 当前边界：没有长期记忆、写 Tool、多 Agent 和生产 SLA。
- 生产扩展：先扩大 Eval，再按失败归因升级存储、检索和稳定性。
- 连续追问：1 为什么不是 Chatbot？2 为什么需要 LLM？3 哪些逻辑确定性？4 最大难点？5 最大 Bad Case？6 如何验收？7 为什么单 Agent？8 Java/Python 如何分工？9 RAG 做什么？10 如何失败？11 如何恢复？12 如何防幻觉？13 如何防越权？14 性能瓶颈？15 技术债？16 下一阶段？

## B. Skill（15+）

**问题：Skill 与 Intent、Tool、Agent 有什么区别？**

- 30 秒口述：Intent 是任务标签，Tool 是一次动作，Skill 是完成一类任务的能力契约；Skill 没有独立模型和自治 Loop，所以不是 Agent。
- 深挖：SkillSpec 聚合实体、allowed tools、Prompt、Context、Progress、Completion、Failure、Budget 与 Security。
- 当前项目：B 层从真实 Prompt/Tool/Progress/Orchestrator 语义提炼四个 Skill。
- 当前边界：没有热加载、远程 Skill 市场或版本治理平台。
- 生产扩展：做注册审核、兼容检查、灰度与指标分 Skill 聚合。
- 连续追问：1 为何不直接暴露所有 Tool？2 Skill 生命周期？3 谁加载？4 谁卸载？5 如何版本化？6 required_entities？7 allowed_tools 双层白名单？8 Progress 如何定义？9 Completion 放哪？10 FailurePolicy？11 ContextPolicy？12 PromptPolicy？13 Skill 间切换？14 Skill 冲突？15 为什么不是固定 Workflow？16 为什么不是 SubAgent？

## C. Router（15+）

**问题：Router 为什么不能规划 Tool？**

- 30 秒口述：Router 只决定“这是哪类任务”，任务内下一动作由模型结合 Observation 决定；否则路由规则会变成不可扩展的固定工作流。
- 深挖：RoutingResult 包含 intent、skill、entities、confidence、source、intent_switch，不含 tool sequence。
- 当前项目：支持首轮识别、WAITING_INPUT 短补参和明确切题。
- 当前边界：没有训练专用路由模型。
- 生产扩展：低置信度 LLM router、离线混淆矩阵、灰度 fallback。
- 连续追问：1 Router vs Planner？2 Router vs Registry？3 UNKNOWN？4 confidence？5 rule vs LLM？6 entity extraction？7 短补参？8 intent switch？9 多意图？10 冲突？11 误路由指标？12 如何 fallback？13 是否可跳过 Router？14 如何测？15 安全边界？16 路由缓存？

## D. Prompt（20+）

**问题：Prompt 如何设计且为什么不能承担安全？**

- 30 秒口述：Prompt 用中文描述角色、Skill 目标、动态决策和输出 Contract；它提升模型遵循度，真正安全由 Schema/Harness/下游授权保证。
- 深挖：按 base、decision contract、Skill instructions、runtime context 分区，避免字段重复定义。
- 当前项目：真实 Prompt 支持 Tool/ANSWER/REQUEST_INPUT/HANDOFF 与完整性原则。
- 当前边界：不保存隐藏思维链，不宣称 prompt injection 被 Prompt 单独解决。
- 生产扩展：版本化、离线回放、canary、Provider 差异测试。
- 连续追问：1 System/User 优先级？2 中文 Prompt 价值？3 Tool description？4 Schema 谁是权威？5 示例是否过拟合？6 completeness？7 over-query？8 RAG 何时调用？9 REQUEST_INPUT？10 HANDOFF？11 injection？12 contract mismatch？13 自动修复？14 retry？15 temperature？16 model migration？17 prompt version？18 A/B test？19 token cost？20 是否记录完整 Prompt？21 chain-of-thought？22 如何回滚？

## E. Context Engineering（20+）

**问题：为什么 AgentState 不能直接发给模型？**

- 30 秒口述：State 含身份、计数、失败历史和恢复信息；Context 只投影本轮最小充分信息，降低泄漏、噪声、成本与冲突。
- 深挖：ContextBuilder 通过 Selector、Skill Policy 和 Budget 选择相关 Observation/Evidence/Progress/Tools。
- 当前项目：DecisionContext 不含 authenticated_user_id 和内部认证信息。
- 当前边界：没有复杂自动摘要/压缩系统。
- 生产扩展：按语义相关性、时效、来源与预算做分层压缩并评测信息损失。
- 连续追问：1 State vs Context？2 relevant observations？3 Evidence 选择？4 Tool metadata？5 Progress？6 当前 query？7 历史消息？8 auth 排除？9 token budget？10 截断策略？11 recency？12 stale facts？13 多 Tool 冲突？14 RAG chunk？15 空集合？16 Context version？17 cache？18 compression？19 prompt injection history？20 如何 Eval？21 丢信息怎么办？22 多模型差异？

## F. Memory（15+）

**问题：当前 Memory 保存什么？**

- 30 秒口述：SessionMemory 保存单 Task 可恢复 State，用于 WAITING_INPUT；不是长期画像，也不替代实时 Facts。
- 深挖：key 必须含 session+identity，快照复制，state_version 支持未来冲突控制。
- 当前项目：进程内实现，同会话补参、新会话/跨身份隔离。
- 当前边界：无 Redis、TTL、多实例一致性、长期记忆。
- 生产扩展：checkpoint、CAS、TTL、幂等与数据删除策略。
- 连续追问：1 Session vs Task？2 pending query？3 snapshot？4 deep copy？5 state_version？6 切题？7 TaskStore？8 跨身份？9 新 Session？10 TTL？11 Redis？12 并发写？13 crash recovery？14 GDPR 删除？15 LTM？16 Memory 与 Facts 冲突？

## G. Tool Calling（20+）

**问题：一次 Tool Call 怎样从模型提议变成可信执行？**

- 30 秒口述：Decision 先过 Capability、Argument、Identity、Provenance、Repeat、Budget，再由 Registry 找 Tool；成功结果经 Contract 才生成 Observation。
- 深挖：Schema 验形状，Provenance 验来源，可信身份通过旁路注入。
- 当前项目：5 个只读 Tool，Java 四个 Facts + 一个 Rule Search。
- 当前边界：无写操作、MCP 和动态远程发现。
- 生产扩展：Tool 版本、隔离、并发、熔断、幂等和审批。
- 连续追问：1 allowlist？2 Tool 自描述？3 arguments_schema？4 result_schema？5 userId？6 Java Header？7 HTTP 200？8 envelope？9 malformed JSON？10 contract mismatch？11 timeout？12 connection？13 auth failure？14 unauthorized？15 retryable？16 repeat vs retry？17 tool budget？18 empty list？19 side effects？20 MCP？21 Tool version？22 审计？

## H. Harness（20+）

**问题：Harness 为什么是独立运行时？**

- 30 秒口述：它按阶段组合确定性 Guard，让 Orchestrator 只推进流程、Guard 各守一条规则；Harness 本身不做业务推理。
- 深挖：Tool 前、Answer 前、Failure 三条明确验证链。
- 当前项目：Reference 显式组合九 Guard 和 Timeout/Retry Policy。
- 当前边界：没有写 Tool 补偿、跨服务 Policy engine。
- 生产扩展：策略配置、审计版本、故障注入与 circuit breaker。
- 连续追问：1 CapabilityGuard？2 ArgumentGuard？3 IdentityGuard？4 GroundingGuard？5 EvidenceGuard？6 RepeatGuard？7 LoopGuard？8 CompletionGuard？9 BudgetGuard？10 TimeoutPolicy？11 RetryPolicy？12 顺序为何重要？13 fail-open/closed？14 Guard 错误码？15 Prompt 能替代吗？16 Orchestrator 是否重复判断？17 answer validation？18 empty Evidence？19 request input guard？20 handoff？21 单测？22 性能开销？

## I. RAG（30+）

**问题：RAG 在业务 Agent 中的正确位置？**

- 30 秒口述：RAG 提供可引用的稳定规则知识，不能冒充用户实时资格或订单状态；它也是受 Harness 控制的 Tool。
- 深挖：Catalog→Entry→Chunk→Rewrite→Retrieve→Filter→Rerank→Observation→Evidence，各阶段可独立 Eval。
- 当前项目：小 Catalog 词法检索，Top-1 70%、Top-3 100%。
- 当前边界：无 Embedding、VectorDB、Hybrid、生产 Rerank。
- 生产扩展：先以失败集证明召回瓶颈，再 Hybrid/Rerank。
- 连续追问：1 为什么 RAG？2 为什么不用模型常识？3 rule vs facts？4 catalog schema？5 version？6 chunk？7 chunk size？8 overlap？9 metadata？10 lexical？11 BM25？12 query rewrite？13 synonym？14 filter？15 rerank？16 TopK？17 Recall@K？18 MRR？19 Top1/Top3？20 empty result？21 stale rule？22 conflict rule？23 citation？24 evidence path？25 hallucination？26 embedding？27 vector store？28 hybrid fusion？29 online eval？30 latency？31 cache？32 access control？33 data poisoning？34 rollback？

## J. Eval（20+）

**问题：怎样证明 Agent 改动真的更好？**

- 30 秒口述：分 Contract unit、deterministic harness、retrieval eval、real Provider multi-session、HTTP E2E；失败分类且不把 Infra 混进业务。
- 深挖：PASS/FAIL/INFRA_FAILURE + MODEL/TOOL/CONTEXT/RAG/EVIDENCE/HARNESS/BUSINESS/INFRA。
- 当前项目：192 tests、23/23 E2E、17/20 FULL/0 PARTIAL 等阶段指标。
- 当前边界：样本仍小，不代表生产准确率。
- 生产扩展：版本化数据集、盲测、在线反馈和回归门禁。
- 连续追问：1 unit vs live？2 Fake 的价值？3 禁止 Fake 冒充什么？4 FULL 定义？5 PARTIAL？6 unsupported？7 unnecessary tool？8 evidence failure？9 model timeout？10 tool timeout？11 infra failure？12 classifier？13 evaluator 自测？14 golden set？15 judge model？16 judge bias？17 retrieval eval？18 E2E？19 sample size？20 statistical variance？21 regression gate？22 bad case ledger？

## K. Trace（15+）

**问题：如何让 Agent 可观测又不泄密？**

- 30 秒口述：记录 trace/task、stage、action、Tool/Model 次数、耗时、稳定错误码和状态转换；敏感字段统一 sanitizer。
- 深挖：Trace 是追加事件，不是 State 或完整 Prompt 仓库。
- 当前项目：安全 Trace/metrics 接口与真实运行摘要。
- 当前边界：无 Prometheus、分布式 tracing 后端和正式 SLA dashboard。
- 生产扩展：OpenTelemetry、采样、关联 Java trace、告警。
- 连续追问：1 trace_id？2 task_id？3 session 是否记录？4 userId？5 prompt？6 provider response？7 stack？8 model call？9 tool call？10 state transition？11 latency？12 token？13 cost？14 sampling？15 retention？16 correlation？17 alert？

## L. Security（15+）

**问题：模型如何被限制在业务授权内？**

- 30 秒口述：身份由 Gateway 建立，Context 不暴露，Tool Schema 不接收，Identity/Provenance Guard 拦截，下游 Java 再授权。
- 深挖：Prompt、能力、参数、身份、下游五层纵深防御。
- 当前项目：userId injection、跨身份 Session、Evidence、未知实体安全测试。
- 当前边界：无完整威胁建模平台和外部红队。
- 生产扩展：策略版本、密钥托管、审计、红队和最小权限服务账号。
- 连续追问：1 prompt injection？2 indirect injection？3 userId spoof？4 Header？5 SQL/Redis？6 arbitrary tool？7 data exfiltration？8 cross-session？9 cross-identity？10 evidence forgery？11 parameter forgery？12 logs？13 secrets？14 Java authorization？15 fail closed？16 RAG poisoning？17 write approval？

## M. Production（25+）

**问题：从当前版本到生产还差什么？**

- 30 秒口述：需要持久 checkpoint、并发一致性、限流熔断、模型路由、容量与 SLO、数据治理；这些是 C 层，不假装已实现。
- 深挖：按 Gateway、Model、Java、RAG、Memory 四个依赖域设置 timeout/error budget 和恢复策略。
- 当前项目：功能/安全闭环和局部 telemetry 已有。
- 当前边界：无 P95/QPS/SLA、多实例和正式 on-call。
- 生产扩展：先压测和故障注入，再逐项引入而非一口气重构。

## N. MCP / Skill / A2A / Multi-Agent（20+）

**问题：这些概念如何区分，何时引入？**

- 30 秒口述：Skill 是进程内任务契约；MCP 是工具/资源互操作；Agent 是自治决策主体；A2A 是 Agent 间协议。当前只需要单 Agent 多 Skill。
- 深挖：先证明组织、权限、上下文或并行边界，再承担通信与一致性成本。
- 当前项目：AgentTool Protocol 可以未来适配 MCP，但目前没有接入。
- 当前边界：没有 Agent network、delegation 或跨进程协商。
- 生产扩展：从单个隔离 worker 试点，定义输入输出、超时、取消、身份传播和 Trace。
- 连续追问：1 Skill vs Tool？2 Skill vs Agent？3 MCP server/client？4 discovery？5 resources？6 prompts？7 auth？8 transport？9 A2A？10 delegation？11 task ownership？12 shared memory？13 context isolation？14 parallelism？15 consensus？16 failure propagation？17 retry ownership？18 trace correlation？19 cost？20 security？21 when not to use？22 migration path？

## 使用建议

每次随机选 3 个主问题，沿追问池连续回答 10 分钟。所有回答最后都补一句“当前做到哪里、没做到哪里、用什么指标决定升级”，避免夸大。
