# 阅读指南

本目录是可运行、可审计的架构参考，不是另一套生产实现。阅读前必须先接受三条事实：真实项目已有闭环，Reference 对职责做显式重构，生产扩展不等于已落地。

## 三层标签

- A：真实项目已有能力或真实验收结果。
- B：从真实语义抽取的参考架构，目的是让边界更清晰。
- C：生产化扩展设计，当前真实项目未实现。

每份文档出现“未来可做”时，应能在 `02_真实项目映射.md` 找到 C 层标记；找不到就属于口径缺陷。

## 三种阅读方式

### 快速了解（15 分钟）

读 README、01、02、18，再读 examples/01。目标是能用一分钟说清动态 Agent Loop 和 Evidence Grounding。

### 源码学习（1–2 小时）

按 17 的 Level 1–11 阅读。每一层运行相应 unittest，不需要先看 production 扩展。

### 面试准备（45–60 分钟）

先读 22 的数据口径，再按 21 连续拷打；用 16 扩展追问，用 23 回答“为什么没上更复杂方案”。

## 阅读时始终追问

1. 谁拥有这个状态？
2. 谁能修改它？
3. 模型能看到什么，绝不能看到什么？
4. 这是模型建议还是确定性约束？
5. 失败会不会被误认为业务事实？
6. 指标属于哪个阶段、多少样本？
7. 这是 A、B 还是 C？

## 最小运行方式

```text
python architecture-reference/scripts/audit_reference.py
python -m compileall architecture-reference/src
python -m unittest discover architecture-reference/tests -v
```

执行 compileall 后应清理 `__pycache__` 和 `.pyc`；Reference 自带 `.gitignore` 防止缓存进入版本管理。

## 完成标准

源码可编译、102 项以上测试通过、7 个案例可从输入追到终态、A/B/C 标记一致、C 层文件醒目标注、缓存清理后，才可称 Reference 内容完整。
