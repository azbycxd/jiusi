# 源码学习导航：Level 1–11

每一层先回答“谁拥有状态、谁能看到身份、谁负责约束”，再进入下一层。无需一次理解全部生产扩展文件。

## Level 1：请求与可信身份
- 文件：`gateway/request_context.py`、`gateway/request_gateway.py`、`app/chat_api.py`
- 要理解：HTTP 字段和认证层身份如何分离；模型为什么永远看不到可信身份。
- 不必理解：真实 Web Server、中间件和 OAuth 实现。
- 自测：指出恶意消息中的 userId 为什么不能覆盖 RequestContext。
- 面试题：身份边界为什么必须在 Agent 之前建立？

## Level 2：Router 与 RoutingResult
- 文件：`routing/base.py`、`intent_router.py`、`routing_result.py`
- 要理解：Router 识别任务/实体，不规划 Skill 内 Tool 顺序。
- 不必理解：复杂意图模型训练。
- 自测：解释 UNKNOWN、补参和 intent switch 的不同处理。
- 面试题：Router 和 Planner 有什么本质区别？

## Level 3：Skill 五件套与 Registry
- 文件：`skills/base.py`、`skills/registry.py`、四个 Skill 子目录。
- 要理解：Prompt、Context、Completion、Failure Policy 如何定义完整能力。
- 不必理解：插件热更新和远程 Skill 市场。
- 自测：列出 participation 与 order Skill 的差异。
- 面试题：为什么 Skill 不是 Tool，也不是 SubAgent？

## Level 4：State 与 Progress
- 文件：`agent/state.py`、`progress/skill_progress.py`。
- 要理解：TaskStatus、Observation、计数器、Possible/Required 与 Obligation status 生命周期。
- 不必理解：数据库持久化和分布式锁。
- 自测：说明失败 ToolResult 为什么保留、却不生成 Observation。
- 面试题：Evidence-driven Progress 如何同时防提前回答和静态扫 Tool？

## Level 5：Context Engineering
- 文件：`context/decision_context.py`、`selector.py`、`builder.py`、`compressor.py`。
- 要理解：State != Context；只投影相关 Observation/Evidence/Tool。
- 不必理解：复杂摘要模型和自动压缩系统。
- 自测：列出必须排除的身份与运行计数字段。
- 面试题：完整历史为什么可能降低决策质量？

## Level 6：Decision Contract
- 文件：`decision/actions.py`、`schemas.py`、`validator.py`、`model.py`。
- 要理解：CALL_TOOL、ANSWER、REQUEST_INPUT、HANDOFF 的互斥字段。
- 不必理解：Provider SDK 细节。
- 自测：构造同时含 tool_name 和 final_answer 的非法 Decision。
- 面试题：Schema mismatch 应重试、转人工还是忽略？

## Level 7：Harness 与 Guard
- 文件：`harness/runtime.py` 及九个 Guard、Timeout/Retry Policy。
- 要理解：Tool 前、Answer 前、失败后的确定性检查顺序。
- 不必理解：业务原因推理；Harness 不负责它。
- 自测：分别触发非法 Tool、伪造 Evidence、超预算。
- 面试题：为什么 Prompt 约束不能代替 Harness？

## Level 8：Tool、Facts 与可信事实
- 文件：`tools/base.py`、`arguments.py`、`registry.py`、`tools/java/`、`tools/rag/`。
- 要理解：显式 allowlist、参数 Schema/Provenance、Java 身份注入、稳定 ToolResult。
- 不必理解：真实 Java 业务源码；Reference 不访问它。
- 自测：证明 Tool arguments 中不存在 userId。
- 面试题：HTTP 200 为什么仍可能是 Tool failure？

## Level 9：Observation、Evidence 与 Provenance
- 文件：`observations/observation.py`、`evidence.py`、`provenance.py`。
- 要理解：成功结果冻结、路径寻址、空集合 Evidence。
- 不必理解：知识图谱和向量索引。
- 自测：区分 `candidate_teams=[]`、字段不存在、Tool timeout。
- 面试题：Evidence 与参数 Grounding 为什么必须拆开？

## Level 10：Orchestrator、Memory 与恢复
- 文件：`agent/orchestrator.py`、`memory/session_memory.py`、`task_store.py`。
- 要理解：有限循环、统一 Harness、WAITING_INPUT、切题和身份隔离。
- 不必理解：Redis Checkpoint 与长期记忆实现。
- 自测：模拟“缺 activityId”后补参和切换订单任务。
- 面试题：REQUEST_INPUT 与 HANDOFF 为什么不同？

## Level 11：RAG、Eval、Trace 与生产边界
- 文件：`rag/`、`eval/`、`observability/`、`production/`。
- 要理解：规则/实时 Facts 分工；失败分类；安全 Trace；C 层只是设计。
- 不必理解：未落地的 VectorDB、MCP、多 Agent 工程细节。
- 自测：解释 Top-3 100%、23/23 HTTP 与 17/20 FULL 各衡量什么。
- 面试题：什么指标出现时才升级 Hybrid RAG 或多 Agent？

完成后用 `examples/01` 从头追一次对象变化，再运行 `scripts/audit_reference.py`。
