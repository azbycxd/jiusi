# 生产级追问回答模板

面对“为什么不用更复杂方案”，统一按五段回答：①当前实现；②为什么现在不复杂化；③什么失败条件会触发升级；④升级路径；⑤如何用指标验证。这样既不回避生产问题，也不把 C 层说成已实现。

## VectorDB / Hybrid RAG

1. 当前：约 15 条治理规则使用词法召回，既有 Eval 为 Top-1 70%、Top-3 100%。
2. 不复杂化：小规模、强关键词场景中向量基础设施收益不足以抵消索引、更新和调参成本。
3. 触发条件：规则规模扩大、同义表达使 Top-3 下降、错误归因主要落在 retrieval。
4. 升级：BM25 + Embedding hybrid，metadata filter，再以 reranker 排序；保留规则版本和引用。
5. 验证：离线 Recall@K/MRR、线上 Evidence 命中、延迟与成本，对照词法基线 A/B。

## Multi-Agent / A2A

1. 当前：单 Agent + 多 Skill，共享一次受控 Loop。
2. 不复杂化：任务依赖短、Tool 数量少，多 Agent 会增加通信、状态一致性和可观测成本。
3. 触发条件：出现独立角色权限、可并行长任务、上下文互相污染或组织边界。
4. 升级：先拆有清晰输入输出的 worker，再定义任务协议、状态归属、超时和 A2A 失败语义。
5. 验证：端到端成功率、墙钟耗时、额外 Token、跨 Agent 错误和恢复率。

## Long-Term Memory

1. 当前：SessionMemory 只保存未完成 Task；真实 Facts 每次查询权威系统。
2. 不复杂化：长期记忆可能过期、污染身份边界，且当前诊断不依赖长期个性化。
3. 触发条件：跨 Session 偏好确有收益，且可定义用户同意、TTL、删除和冲突策略。
4. 升级：分离用户偏好、事件摘要与权威 Facts，加入 consent、版本和可撤销机制。
5. 验证：个性化收益、错误记忆率、删除合规、跨身份泄漏测试。

## MCP

1. 当前：内部 AgentTool Protocol + 显式 Registry。
2. 不复杂化：本地 5 个 Tool 接口稳定，没有跨宿主发现需求。
3. 触发条件：工具由多个团队/运行时提供，需要标准发现、资源和权限声明。
4. 升级：将现有 Tool Contract 映射 MCP server/client，Harness 仍在信任边界内执行。
5. 验证：兼容性、权限最小化、超时/取消、schema 演进和审计覆盖。

## P95 / QPS / SLA

1. 当前：记录单次 model/tool duration，但没有正式容量数据或 SLA。
2. 不复杂化：功能和安全 Contract 先稳定，样本流量不足以给可靠分位数。
3. 触发条件：进入预发布、有代表流量模型和明确业务 SLO。
4. 升级：压测 Gateway/LLM/Java/RAG 各阶段，设置 timeout budget、限流和容量冗余。
5. 验证：P50/P95/P99、最大稳定 QPS、错误率、资源水位和依赖错误预算。

## Circuit Breaker / Fallback

1. 当前：有限 timeout/retry 后 HANDOFF，不宣称已实现熔断。
2. 不复杂化：单机参考阶段先保证失败不误判，不引入跨请求共享状态。
3. 触发条件：下游持续错误导致重试风暴、资源耗尽或尾延迟放大。
4. 升级：按依赖隔离 breaker、half-open 探测、fallback 只返回明确降级信息。
5. 验证：故障注入下的恢复时间、错误放大率、错误降级答案计数。

## 带副作用 Tool

1. 当前：5 个 Tool 全是只读，模型不能修改订单或活动。
2. 不复杂化：写操作涉及资金/库存/权益，风险模型完全不同。
3. 触发条件：业务明确授权可执行动作，并能提供幂等和补偿 Contract。
4. 升级：二次确认、最小权限、幂等键、审批、事务/补偿、不可抵赖审计。
5. 验证：重复提交、超时未知状态、补偿失败、越权和人工确认 E2E。

## Redis Checkpoint / 多实例

1. 当前：进程内 SessionMemory，适合 Reference 与单进程验收。
2. 不复杂化：当前目标是验证控制语义，不是承载生产集群。
3. 触发条件：多实例路由、进程重启恢复和并发同 Session 请求成为实际需求。
4. 升级：Redis checkpoint + version/CAS + TTL + 幂等事件，明确锁粒度。
5. 验证：并发冲突、宕机恢复、过期、跨身份和重复请求测试。
