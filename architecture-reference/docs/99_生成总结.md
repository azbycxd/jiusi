## 最重要的设计结论

- 模型负责不确定决策，Harness 负责确定性边界。
- Router 只选 Skill；Progress 管完整性但不是固定 Workflow。
- Tool 参数 Schema、Parameter Provenance、Answer Evidence 是三个不同问题。
- 失败 ToolResult 必须留痕，但绝不能生成业务 Observation。
- 可信身份不进入模型 Context 或 Tool arguments。
- RAG 解释规则，Java Facts 提供实时实例状态。
- REQUEST_INPUT 表示可补参，HANDOFF 表示能力或可靠性不足。
- SessionMemory 不是长期记忆；Trace 不是 State。

## 指标事实

真实项目既有记录为 Python 192 passed、最终 HTTP 23/23、Unsupported/Evidence failure/Unnecessary tool 均为 0；Rule RAG Top-1 70%、Top-3 100%；开放诊断 17/20 FULL、0 PARTIAL，其余 Provider timeout→HANDOFF。它们属于不同评测维度，不得合成为生产准确率或 SLA。

Reference v1.0 的 102 项确定性 unittest 全部保留；v1.1 新增 22 项后为 124 项全通过，
源码/文档有效行以每次 `scripts/audit_reference.py` 输出为准。自动审计同时禁止核心路径继续使用
`progress_dimensions` 或 `Tool dimension → completion`。
