# 生产稳定性

> 【C 生产扩展，当前未实现】Reference 组件可确定性测试，不代表已部署。

## 多维限流

TokenBucket 支持突发与持续补充；SlidingWindowCounter 更直观地限制窗口请求数。生产应按
user、tenant、model provider、skill 和 global 多维组合，使用共享原子存储，区分拒绝、
排队和降级，避免一个租户耗尽全部 Provider 配额。

## Circuit Breaker

CLOSED 正常放行并累计失败；超过阈值进入 OPEN，cooldown 内快速失败；到期进入 HALF_OPEN，
只允许有限 probe；probe 成功关闭，失败重新打开。Provider 持续 timeout 时不能让全部请求
继续打爆下游。窗口、阈值和 cooldown 必须用故障演练/流量数据确定。

## Fallback

主模型失败可在兼容 Structured Output/Tool Calling 的备用模型间切换。实时 Facts 服务失败
必须 HANDOFF，绝不允许 RAG 冒充当前订单、资格或活动状态。规则检索失败也不能凭模型记忆
编造平台政策。Fallback 本身要计数、限次并进入 Trace。

## Model Routing

ModelProfile 描述 Context 上限、Tool/Structured Output 能力、质量/延迟/成本层级。
classification 可候选小模型，开放式多事实诊断要求更强模型；选择还受 latency budget、
cost budget 和 Context 长度约束。当前项目没有生产 Model Router。

## Cache

Business Cache 缓存明确业务键；Semantic Cache 按语义复用答案；Prompt Prefix Cache 复用
稳定前缀。Rule QA 较适合缓存。实时订单/资格禁止只按相似 Query 命中；SemanticCacheKey
至少含 user scope、business ID、intent、time bucket、permission scope 和 normalized query。

## Checkpoint 与并发

CheckpointStore 提供 save/load/version/CAS。多实例更新同一 task_id 时用 state_version
阻止丢更新，必要时加短租约 per-task lock；CAS 冲突重读，不盲目重试旧 Decision。TTL 到期
和 Session 删除要有审计。Checkpoint 用于恢复运行，Long-Term Memory 用于历史复用。

## 故障恢复矩阵

| 故障 | 当前安全行为 | 生产扩展 |
|---|---|---|
| Provider timeout | 有限重试后 HANDOFF | breaker、备用模型 |
| Java timeout | 只读有限重试，不推断业务失败 | breaker、连接池、告警 |
| RAG 空结果 | 不生成规则 Evidence | Catalog 诊断、回归集 |
| Evidence mismatch | 拒绝 ANSWER | 安全告警、Bad Case |
| State CAS 冲突 | 当前未部署共享存储 | 重读/重算、task lock |
| 写动作部分失败 | 当前无写 Tool | Saga/补偿/人工对账 |

## 运维闭环

指标、Trace、错误预算、告警、Runbook、故障演练、Canary 和 Rollback 必须一起设计。
ENVIRONMENT/PROVIDER/TOOL/PRODUCT 失败应分开，避免为基础设施波动错误修改 Prompt 或业务逻辑。
