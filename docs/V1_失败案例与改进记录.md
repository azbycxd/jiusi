# V1 失败案例与改进记录

本记录如实保留 V1 联调中观察到的坏案例、已采取的最小修复，以及明确不在 V1 扩展范围内的事项。

| 编号 | 现象或风险 | V1 处理 | 当前结果 / 后续方向 |
| --- | --- | --- | --- |
| 1 | Provider 可能返回空字符串、空对象或 `null` 等协议噪声。 | 决策归一化与判别联合 Schema 在 Harness 层校验。 | 不合法决策安全转人工，不执行 Tool。 |
| 2 | Provider 可能输出扁平字段或把不属于当前 action 的字段混入决策。 | `CALL_TOOL`、`ANSWER`、`HANDOFF` 使用 action 绑定的 Schema。 | 非法字段组合被拒绝，不产生越权副作用。 |
| 3 | Evidence 路径可能带固定 `facts.` 前缀。 | 只规范该固定前缀，随后严格验证 Evidence 路径。 | 不接受任意自由路径改写。 |
| 4 | Handoff 的 `missing_information` 可能由字符串而非数组返回。 | 只对非空字符串做单元素列表归一化。 | 协议兼容，但最终用户回复仍固定为安全转人工文案。 |
| 5 | Provider 的 Handoff 元数据可能出现并不存在的能力描述。 | 不把模型的原始元数据直接作为客服答复；最终边界只输出安全转人工。 | V1 不 Prompt-tune；V2 应做系统化模型质量评估与提示词迭代。 |
| 6 | 一次早期真实 HTTP 通用咨询出现模型协议失败并返回安全 Handoff。 | 未伪造成功、未硬编码答案；后续在相同真实 HTTP 入口复测为 `ANSWER / FINISHED / tool_call_count=0`。 | 记录为 Provider 输出波动；V1 安全回退有效，V2 需持续评测其稳定性。 |
| 7 | 真实模型单次调用耗时和 token 量存在波动。 | Trace 只记录安全遥测（模型名、次数、耗时、token usage）。 | V2 再评估超时、成本、重试策略和性能目标。 |
| 8 | Java 或网络临时不可达。 | `TOOL_CONNECTION_ERROR` 映射为可重试 ToolResult，达到有限上限后 Handoff。 | 已通过临时错误 base URL 的真实 HTTP 流验证；不影响正常服务。 |
| 9 | 模型 Provider 临时不可达。 | 沿用既有模型错误映射和有限模型重试，最终安全 Handoff。 | 已通过临时错误 Provider base URL 的真实 HTTP 流验证；无 Fake 回退。 |
| 10 | 内存 Session 不支持跨进程。 | V1 保持 `SessionMemory` 的进程内实现和深拷贝隔离。 | 延期 Redis、TTL、多实例并发、分布式锁和版本控制。 |
| 11 | 开发认证 Header 不适合生产。 | 仅由可信 AgentState / Client 注入，绝不暴露给模型。 | 生产接入真实认证上下文、密钥管理和网关策略时单独验收。 |
| 12 | Trace 先前只有内存记录，HTTP 服务日志不可见。 | 为专用 `group_buy_agent.trace` logger 添加一次性 JSON StreamHandler。 | 真实 HTTP 服务端已看到完整 Trace；后续可接集中化日志平台。 |

## 明确延期，未在 V1 实现

- RAG、退款规则知识库、退款 Tool；
- 长期 Memory、Redis Session、TTL、多实例并发与分布式锁；
- Multi-Agent、额外业务 Tool、真实订单写操作；
- Java 项目源码修改；
- Prompt 大规模调优、成本治理和完整生产可观测性平台。

上述延期不改变 V1 的事实查询、认证边界、有限终止和安全 Handoff 验收结论。
