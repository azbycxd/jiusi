# V1 端到端验收报告

## 1. 验收范围与环境

本次仅操作 `D:\workspace\java\group-buy-agent`，未访问或修改 Java 项目源码。验收使用指定 Conda 环境 `group-buy-agent`：

- Python 可执行文件：`D:\soft\anaconda3\envs\group-buy-agent\python.exe`
- Python 版本：3.11.15
- 本地配置存在性：`LLM_API_KEY`、`LLM_MODEL`、`LLM_BASE_URL`、`LLM_TIMEOUT`、`JAVA_MARKET_BASE_URL`、`JAVA_MARKET_ENABLE_DEV_AUTH_HEADER` 均为 `configured=true`。

配置值、认证 Header、身份标识、完整 Prompt、完整模型响应和密钥均未写入本报告。

## 2. 实际 HTTP 入口

启动本地 FastAPI/Uvicorn 后，`GET /health` 返回 `200` 与 `{"status":"ok","mode":"dynamic-agent-loop"}`。实际验收请求通过 `POST /v1/chat` 进入运行时，而非直接调用 Orchestrator、LLM Client 或 Java Client。

请求体仅包含 `session_id` 与 `message`；可信身份仅由 HTTP Header `X-Authenticated-User-Id` 注入。身份不是请求体、模型工具参数或工具 Schema 的字段。

## 4. 真实订单 Facts 链路

场景 B 的真实调用链为：

```text
POST /v1/chat
  -> OrderFactsOrchestrator
  -> RealLLMDecisionModel（第一次真实 Provider 请求）
  -> Harness 校验
  -> get_order_facts
  -> OrderFactsTool
  -> JavaMarketClient（真实 HTTP）
  -> Java Order Facts API -> MySQL 路径
  -> ToolResult / ContextState.order_facts / evidence
  -> RealLLMDecisionModel（第二次真实 Provider 请求）
  -> Evidence 校验 -> FINISHED
```

本次 Java 返回的事实为：订单 `CLOSE`；拼团 `PROGRESS`，目标人数 `3`、锁定人数 `0`、已完成人数 `0`；活动 `EFFECTIVE`；引用 `teamId=18781389`、`activityId=100123`。这些 Facts 由 `OrderFacts` 合同解析后进入 `ToolResult.data`、`ContextState.order_facts` 和结构化 Evidence；Python 未新增任何基于订单状态的诊断 `if/else` 规则。

工具参数只包含 `outTradeNo`。认证用户来自可信 AgentState，并由 Java Client 在开发 Header 模式下组合请求；模型不能构造 `userId`、Header、URL、SQL、`teamId` 或 `activityId`。

## 5. Trace 与遥测

场景 B 的真实服务端 Trace 顺序为：

```text
ROUTED
-> MODEL_DECISION(CALL_TOOL)
-> TOOL_CALL(get_order_facts)
-> TOOL_RESULT(success=true, 13 ms)
-> MODEL_DECISION(ANSWER)
-> FINISHED
```

该请求的第一轮模型调用为 `gpt-5.5`、约 9200 ms、5193 tokens；第二轮约 15590 ms、5541 tokens。Trace 还记录 `trace_id`、`session_id`、迭代次数、工具调用次数、重试次数、模型调用次数、错误码和耗时。日志未出现 API Key、认证 Header、可信身份、完整 Prompt、完整 Provider 响应或 Java 堆栈。

## 6. Session、终止与恢复

`SessionMemory` 以 `session_id` 保存深拷贝 State。新增回归用例证明不同 session 的订单号和可信身份互不串写；既有用例覆盖缺槽位时进入 `WAITING_USER` 并在后续输入恢复，以及终态 session 的后续消息创建新的任务 State。工具与模型均有独立的有限重试计数和上限；上限到达后进入 `HANDOFF` 或明确失败状态，不存在无限循环。
