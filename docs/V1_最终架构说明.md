# V1 最终架构说明

## 1. 运行时结构

```text
HTTP Client
  |  POST /v1/chat {session_id, message}
  |  X-Authenticated-User-Id（可信边界）
  v
FastAPI app.main
  v
OrderFactsOrchestrator
  |- SessionMemory: 按 session 保存/恢复深拷贝 AgentState
  |- Router: 只产生 RoutingResult
  |- DecisionStage / RealLLMDecisionModel
  |     -> OpenAI-compatible Provider
  |- Harness: AgentDecision Schema、Evidence、Capability、参数校验
  |- ToolRegistry allowlist: 仅 get_order_facts
  |     -> OrderFactsTool
  |          -> JavaMarketClient
  |               -> Java Order Facts HTTP API -> MySQL
  |- TerminationPolicy: iteration / tool retry / model retry 有限终止
  `- TraceRecorder: 脱敏结构化 Trace
```

## 2. 责任边界

| 模块 | 责任 | 不负责的事项 |
| --- | --- | --- |
| HTTP API | 校验不可信请求体，接收可信身份 Header，返回最小响应。 | 不接受 body 中的 userId。 |
| Router | 产生结构化意图和订单号候选。 | 不修改 Tool 结果、不执行 Tool。 |
| Orchestrator | 持有 State、执行有限 Loop、应用路由和 Tool 结果、终态保存。 | 不依据订单状态编写自然语言诊断规则。 |
| RealLLMDecisionModel | 通过真实兼容 Provider 提出结构化决策。 | 不能直接执行 Tool、读身份或绕过 Harness。 |
| Harness | 验证 action、allowlist、参数、Evidence。 | 不把模型输出当作可信事实。 |
| ToolRegistry / OrderFactsTool | 只允许 `get_order_facts`，返回统一 ToolResult。 | 不修改 AgentState，不接受 userId 工具参数。 |
| JavaMarketClient | 根据可信 State 身份组装 Java HTTP 请求，解析 Envelope 与 Facts Contract。 | 不生成客服诊断。 |
| SessionMemory | session 内恢复与 session 间深拷贝隔离。 | 不提供 Redis、TTL 或分布式一致性。 |
| TraceRecorder | 记录可观测控制事件和安全遥测。 | 不记录密钥、Header、完整 Prompt/Provider 响应或堆栈。 |

## 3. 动态 Agent Loop

无工具需求时：

```text
User -> LLM ANSWER -> Evidence Validation -> FINISHED
```

订单事实需求时：

```text
User -> LLM CALL_TOOL(outTradeNo only)
     -> Harness Validation
     -> get_order_facts
     -> Java Facts -> ToolResult / ContextState.order_facts / Evidence
     -> LLM ANSWER(used_evidence)
     -> Evidence Validation -> FINISHED
```

当前能力外、协议非法、工具/模型错误达到上限时：

```text
... -> stable safe Handoff / explicit failure -> persisted terminal state
```

## 4. AgentState 与安全性

`AgentState` 将 Capability、Context 和 ControlState 分离。可信 `authenticated_user_id` 位于 State，不出现在 LLM Tool Schema；模型的 `get_order_facts` 参数只能是 `outTradeNo`。`ToolResult` 必须显式表达 `success`、`error_code`、`message`、`data`、`evidence`、`retryable`、`source`，因此“Python 未抛异常”不等价于业务成功。

终态转换基于当前 State 进行，保留已取得的 Facts、Evidence 和 ToolResults；同一 session 的终态后续新消息会开始新任务，非终态缺槽位会恢复同一 State。越权订单查询在 Java 返回 `ORDER_NOT_FOUND_OR_NOT_AUTHORIZED` 后仅给出不泄露事实的用户文案。

## 5. V1 的刻意边界

V1 已具备真实 LLM、真实 Java Order Facts、MySQL 调用路径验证、有限重试、认证边界和 Trace。它尚未包含 RAG、退款事实或规则、长期/分布式 Memory、Multi-Agent、写操作或生产认证网关；这些均不是 V1 的隐含能力。
